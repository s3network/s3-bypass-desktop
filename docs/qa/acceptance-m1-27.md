## 1. Scope & method

### 1.1 What "acceptance" means here

BRIEF §2 enumerates 7 P0 items; `docs/plans/milestones.md` M1 DoD #1 requires all of them
"demonstrated end-to-end on macOS **and** Linux (manual acceptance script by `product-manager`)".
This pass therefore did four things, adversarially:

1. **Traceability audit** — every AC in US-01..US-07 → ≥ 1 TC ID in `m1-test-plan.md` §1–§8
   (strategy §1 requirement); plan counts reconciled against IDs actually present in `tests/`.
2. **Shipped-behavior audit** — each BRIEF §2 claim checked against **current code** (not board
   notes): what is wired natively vs. only unit-tested at module level vs. not wired at all.
3. **Evidence audit** — local test/gate re-runs (allowed scope), CI matrix + run state, RED→GREEN
   commit chain, security-gate state, open issues.
4. **Docs spot-checks** — analysis/plan/QA docs vs. shipped behavior (requested examples +
   fresh finds).

### 1.2 Environment constraints (recorded, not fought)

- The user's VPN holds `127.0.0.1:10808` → the two port-dependent files
  (`tests/unit/core-supervisor.test.ts`, `tests/unit/core-supervisor-hardening.test.ts`, 18 cases)
  and the E2E smoke **cannot run locally**; their barriers fail by design (verified environmental —
  these same cases pass on CI where the port is free). Not re-attempted here.
- E2E (`npm run test:e2e`) is **not in CI** (deferred per `docs/qa/e2e-ci-proposal.md`, strategy
  §2 L3; `ci.yml` sets `ELECTRON_SKIP_BINARY_DOWNLOAD=1`) → last local evidence is the M1-24 batch.
- **No Linux desktop exists** in this environment → L4 rows needing a real GNOME session or a
  packaged build cannot be executed here (see §2, §7).
- Manual macOS L4 rows were **not** executed: they require a port-free window (VPN) and real
  `networksetup` round-trips, which must not be run against the user's live VPN/proxy setup
  without a controlled window (PRD §7 "Proxy safety" demands before/after snapshots).
